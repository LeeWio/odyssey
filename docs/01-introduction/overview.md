# 项目概述（Overview）

## 定位

Odyssey 是一个围绕**内容创作、个人表达与长期积累**构建的个人数字空间。

它起源于博客，但目标并不是成为另一个博客系统。

随着产品的发展，Odyssey 将逐步承载更多形式的内容，包括：

- 文章（Articles）
- 短内容（Notes）
- 图片（Gallery）
- 音乐（Music）
- 股票记录（Stocks）
- 研究笔记（Research）
- 收藏（Collections）

这些内容并不是彼此独立的功能，而是共同组成一个持续成长的个人空间。

---

## 为什么构建 Odyssey

互联网上已经存在大量优秀的博客系统、CMS 和内容平台。

但它们大多数都围绕：

- 发布频率
- 阅读量
- 点赞
- 评论
- 推荐算法
- 模板化页面

进行设计。

Odyssey 希望关注另一件事情：

**如何让一个人的内容，更真实、更自然地长期沉淀下来。**

这里没有「必须每天更新」的压力，也没有为了提高停留时间而设计的复杂交互。

产品更关注：

- 内容本身
- 阅读体验
- 长期积累
- 个人表达
- 产品品质

---

## 产品目标

Odyssey 希望成为一个能够长期演进的个人产品，而不仅仅是一个博客。

它应该能够随着时间不断扩展，而不失去整体的一致性。

未来无论增加：

- 图片
- 音乐
- 评论
- 股票
- AI
- 新的内容类型

都应该保持：

- 同一套设计语言
- 同一套交互体验
- 同一套设计系统
- 同一套工程规范
- 同一套产品理念

功能不断增加，但产品仍然像同一个产品。

---

## 当前基础

目前项目已经确定以下基础方向：

### 产品

- 以内容为核心（Content First）
- 阅读体验优先于互动体验
- 首页强调品牌表达
- 评论作为阅读的补充，而不是正文的一部分

### 设计

- HeroUI 作为唯一组件基础
- Semantic Colors 作为颜色体系
- Tailwind Theme 驱动样式
- Motion 用于解释交互，而不是制造视觉效果

### 工程

- Feature First 目录结构
- Component Composition 优于重复开发
- Tailwind 负责 Layout 与 Spacing
- HeroUI 负责组件能力
- 所有设计决策均通过文档进行约束

这些基础原则构成了 Odyssey 的长期架构。

---

## 文档目标

本项目文档并不是 HeroUI、React 或 Tailwind 的教程。

它主要记录：

- 产品为什么这样设计
- 系统为什么这样实现
- 哪些规则必须遵守
- 哪些方案已经确定
- 哪些仍处于实验阶段

文档的目标不是帮助学习技术，而是帮助维护产品的一致性。

任何新的页面、组件或功能，都应首先遵循文档，而不是重新制定规则。

## 最终原则

Odyssey 不是一系列功能的集合。

它是一个围绕个人表达不断成长的数字空间。

每一次新增功能，都应该让整个产品变得更加完整，而不是更加复杂。

> **One identity. Multiple expressions.**
