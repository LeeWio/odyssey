# ADR-0002: Documentation Structure

## Status

Accepted

## Context

Project knowledge was spread across root-level notes and implementation files. That made it harder to onboard contributors or reason about future work.

## Decision

Use `docs/` as the canonical product and engineering knowledge base.

## Consequences

- project context is easier to discover
- architecture and product decisions can be tracked over time
- future contributors have a single place to understand the system
