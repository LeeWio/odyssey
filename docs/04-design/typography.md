# Typography

## 定位

Typography 不仅承担信息传递的职责，也是产品视觉语言的重要组成部分。

在 Odyssey 中，字体系统需要同时满足**品牌表达**与**内容阅读**两种场景，并保持一致的设计语言。

---

## 设计目标

Typography 应满足以下目标：

- 为长篇文章提供舒适、稳定的阅读体验。
- 为首页和品牌内容建立鲜明的视觉识别。
- 保持清晰、一致的信息层级。
- 支持未来内容型模块的持续扩展。
- 在不同设备和主题下保持良好的可读性。

---

## 字体角色

项目中的字体分为三类，每种字体只承担一种职责。

### Sans

默认界面字体。

适用于：

- 正文
- UI 文本
- 导航
- 按钮
- 表单
- 列表

应保持中性、清晰且易于阅读。

---

### Display

品牌展示字体。

适用于：

- 首页 Hero
- 大标题
- Landing Page
- 品牌标语
- 重点视觉内容

Display 字体用于建立产品个性，不应用于长篇正文。

---

### Mono

等宽字体。

适用于：

- Code Block
- Terminal
- 数字信息
- 标签
- 技术内容

不应用于普通文章阅读。

---

## 层级规范

Typography 应建立明确的信息层级。

每个页面都应能够快速区分：

- 页面标题
- Section 标题
- 正文内容
- 辅助信息
- Caption
- Metadata

层级应主要通过字号、字重和留白建立，而不是依赖颜色。

---

## 阅读体验

文章是 Odyssey 的核心内容。

因此正文应遵循以下原则：

- 保持舒适的行宽。
- 保持充足的行高。
- 避免过大的字号变化。
- 避免频繁使用粗体强调。
- 保持一致的段落间距。
- 让阅读节奏自然、连续。

Typography 的目标是降低阅读成本，而不是增加视觉表现。

---

## 品牌表达

首页允许更具表现力的 Typography。

例如：

- Display Font
- 大字号标题
- 更宽松的留白
- 更明显的视觉层级

但品牌表达不应影响信息传递效率。

视觉效果始终服务于内容。

---

## 一致性

相同层级应始终保持一致的表现。

例如：

- 所有 H1 保持一致。
- 所有 H2 保持一致。
- 所有正文保持一致。
- 所有 Caption 保持一致。

不要因为页面不同而重新定义字体层级。

---

## 禁止事项

以下做法不符合项目规范：

- 一个页面混用过多字体。
- 使用 Display 字体作为正文。
- 仅依赖颜色表达信息层级。
- 随意调整字号、字重和行高。
- 为单个页面创建新的 Typography 风格。
- 为强调内容大量使用全大写、粗体或高饱和颜色。

---

## 最终原则

Typography 应让用户关注内容，而不是字体本身。

阅读体验保持稳定，品牌表达保持克制。

当新的页面或模块加入时，应复用现有 Typography System，而不是重新建立新的文字风格。

## 富文本正文

编辑器和文章阅读器统一通过 `components/rich-text/prose.ts` 接入 HeroUI
`Typography.Prose` 的官方 `typographyVariants().prose()` 样式。
不引入另一套 Typography 插件。Tiptap 的 `Typography` 扩展只处理智能标点，
不负责字号、行高和块间距。

Markdown 定义内容结构，Word 允许文档模板配置段落样式；两者都没有一套通用的像素间距。
本项目以 HeroUI Prose 为视觉基线，缺少的组合间距使用 Tailwind 标准 spacing scale 补齐。
字号、主题颜色、字重和字体角色仍来自 HeroUI，默认不使用负字距。

| 内容                 | 默认排版              | 来源与组合规则                                                            |
| -------------------- | --------------------- | ------------------------------------------------------------------------- |
| 正文                 | 16px / 28px           | HeroUI `body`；不首行缩进，不默认两端对齐                                 |
| H1                   | 36px / 40px           | HeroUI `h1`；段前 32px，段后 16px                                         |
| H2                   | 30px / 36px           | HeroUI `h2`；段前 32px，段后 16px                                         |
| H3                   | 24px / 32px           | HeroUI `h3`；段前 24px，段后 16px                                         |
| 普通段落和独立块     | 上下 16px             | 对应 Prose 的列表、代码和图片节奏                                         |
| 列表                 | 16px / 28px           | 条目间 8px，嵌套列表上下 8px；多段条目保留段落间距                        |
| 任务列表             | 同普通列表            | 复选框和正文顶部对齐；完成样式仅作用于当前任务首段                        |
| 引用                 | HeroUI Prose 引用     | 保留主题边线、颜色和斜体；内部首尾段落不增加外部留白                      |
| 行内代码             | HeroUI Prose 行内代码 | 保留等宽字体和背景，不套用代码块的 padding                                |
| 代码块               | 14px / relaxed        | 内边距 16px；内部 code 继承字号、行高，长行仅在块内横向滚动               |
| 图片                 | 独立块上下 16px       | 间距归外层文档节点；figure 和 img 不重复加 margin，保留作者宽度和对齐     |
| 图注                 | 14px / 24px           | HeroUI `body-sm`；距图片 8px                                              |
| 表格                 | 主题边线              | 单元格上下 8px、左右 12px；首尾段落不叠加单元格 padding，宽表在容器内滚动 |
| 折叠内容             | HeroUI Accordion      | 外部间距归文档；内部内容沿用正文，保留原生展开和键盘交互                  |
| 分栏                 | 保留作者的横向列布局  | 所有视口保留列宽；沿用列背景和 8px 内边距，编辑时支持拖动与键盘调整       |
| 音频、附件、上传占位 | HeroUI 原生组件       | 外部间距归文档；组件只管理内部布局                                        |
| 视频                 | 16:9                  | 响应正文宽度，不让 iframe 固定尺寸撑破页面                                |
| 数学公式             | KaTeX                 | 行内公式跟随段落；块公式居中并在块内处理横向溢出                          |
| 分隔线               | 上下 32px             | HeroUI Prose 的 `my-8`                                                    |

普通块使用正常文档流的 margin 折叠：相邻两个 16px 留白得到 16px 间距，
不会相加成 32px。标题前的较大 margin 建立章节层级；连续标题收敛为 16px。
文档以及列表项、引用、表格单元格、分栏和折叠面板的首尾内容会消除多余留白。
自定义 React NodeView 的外部 margin 必须放在文档节点层，不放在内部视图里。
明确设置的字体、字号、行高、颜色、缩进和对齐保持有效。

HeroUI Pro 的编辑器 CSS 未分层，会覆盖 OSS Prose 的组件层规则；ProseMirror 也有
独立的 pre 换行规则。共享适配层只在这些冲突以及块间距处使用 Tailwind important
工具类，保持 HeroUI 的原生值。不要在页面或 `styles/globals.css` 重新覆盖正文排版。

排版样本：`/test/rich-text?typography=1`（开发环境），可切换实际编辑与文章阅读组件。
`tests/e2e/rich-text-typography.spec.ts` 在 360 / 768 / 1440px、浅色 / 深色下验证
实际计算样式、相邻块间距、图片加载、长代码滚动、移动端分栏、主题生效、作者格式和
编辑/阅读一致性，并保存两种模式的完整页面截图。视频使用本地测试响应，
该测试验证嵌入布局，不验证外部视频服务或音频资源的播放可用性。
