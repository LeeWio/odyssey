# 动画设计规范 (Animation Design Specification)

> 本文档定义项目中的动画设计原则、架构、动效系统、技术选型、常见模式与开发规范。所有新增动画都应遵循本规范。

---

## Philosophy (设计哲学)

动画不是单纯的视觉装饰，而是表达状态变化、空间关系和操作反馈的功能性工具。

- **目的明确：** 每一个动画都必须解决真实问题——确认操作生效、建立空间关联，或引导用户注意力。
- **内容优先：** 动画绝对不能阻碍用户阅读正文、延迟核心内容显示或阻塞用户操作。
- **保持克制：** 整体风格应当平静、自然、连续。避免过度的弹跳、旋转或剧烈缩放。
- **必须可中断：** 用户操作永远优先。动画必须能立即响应新状态，不允许产生动画排队或强制用户等待。

## Architecture (架构)

我们的动画架构建立在 HeroUI 设计系统之上。

- **HeroUI 基准：** HeroUI 组件是主要的构建块。默认情况下，应将它们视为支持动效的组件。
- **组合优于包裹：** 优先使用 `motion(Component)` 将动画直接组合到 HeroUI 组件上，而不是用毫无语义的 `div` 将其包裹起来。
- **状态驱动：** 动画应该由 React 状态驱动，反映真实的 UI 状态，而不是游离于状态之外。
- **分层策略：** 我们根据交互的复杂度和需求，采用严格的技术分层（CSS -> Motion -> GSAP）。

## Motion System (动效系统)

### Duration (时长)

时长应与状态变化的范围相匹配：

- **微交互 (Micro Interactions)：** `80ms` - `160ms`（例如：悬浮、按压、聚焦）。
- **组件过渡 (Component Transitions)：** `160ms` - `240ms`（例如：Tab 切换、手风琴展开、Tooltip）。
- **区块过渡 (Section Transitions)：** `240ms` - `320ms`（例如：侧边栏展开、页面区块切换）。
- **叙事动画 (Narrative Motion)：** `>400ms`（例如：首屏视觉叙事，仅限于故事性表达）。

### Easing (缓动)

- 使用平滑、自然的缓动曲线。
- **入场动画：** 使用柔和的缓出 (ease-out)，让元素平缓进入视线。
- **出场动画：** 使用更短、更锐利的缓动，迅速清理屏幕空间。

### Spring (弹簧)

- 弹簧物理效果适用于可中断的状态变化、拖拽手势和布局过渡，能带来自然、物理的质感。
- 保持弹簧参数紧凑；避免过度弹跳或过长的阻尼静止时间。

### Distance (位移)

- 保持位移距离较小。大范围的空间移动容易让人失去方向感。
- 优先选择轻微的垂直或水平移动（例如：从 `y: 16` 到 `y: 0`），而不是横跨整个屏幕的移动。

### Scale (缩放)

- 谨慎使用缩放（例如：`scale: 0.95` 用于按压反馈）。
- 避免因缩放导致布局抖动或文本渲染模糊。

## Technology (技术选型)

项目动画只允许使用以下三种方案，选择依据是交互类型，而非个人偏好。

### CSS

仅用于简单、局部、无复杂状态的微交互。

- **适用场景：** Hover、Focus、Active 状态，颜色变化，骨架屏，Spinner，以及简单的透明度变化。
- **选择理由：** 性能开销最低，最适合不依赖 React 状态或复杂时间轴的纯视觉反馈。

### Motion

`motion/react` 是项目中组件级和状态驱动动画的**默认方案**。

- **适用场景：** 进场/出场动画、Layout 动画、Modal/Popover 覆盖层、Tab 指示器、拖拽手势，以及任何与 React State 强相关的动画。
- **选择理由：** 声明式 API，易于与 HeroUI 组合（`motion(Button)`），能优雅地处理中断和布局动画。

### GSAP

仅用于 Motion 和 CSS 不适合完成的复杂编排动画。

- **适用场景：** 滚动驱动动画 (ScrollTrigger)、复杂时间轴、SVG 路径绘制、多元素协同编排。
- **选择理由：** 拥有无与伦比的时间轴控制和滚动同步能力。**不应**用于简单的淡入淡出或状态切换。

## Motion Patterns (动效模式)

### Entry (入场)

- 元素应平滑淡入（`opacity: 0` -> `1`），并伴随短距离的滑入。
- 使用柔和的 ease-out 曲线或带有阻尼的弹簧效果。

### Exit (出场)

- 元素应快速淡出并伴随轻微滑动。
- 出场动画的时长必须短于入场动画，不要让用户等待 UI 消失。

### Overlay (覆盖层)

- Modal、Sheet 和 Popover 出现时，应在视觉上来源于触发该操作的逻辑源头。
- 使用 Motion 处理覆盖层及其背景遮罩的 `AnimatePresence` 进出状态。

### Navigation (导航)

- 对于连续的空间过渡（例如移动 Tab 指示器或 Segment 切换），使用 Motion 的 Layout 动画。
- 如果可以通过平滑过渡完成，应避免让导航元素闪烁或完全替换。

### Feedback (反馈)

- 包括按钮悬浮、焦点环和按压状态等微交互。
- 优先使用 CSS transition 处理 hover/focus，使用 Motion 的 `whileTap` 处理物理按压反馈。

### Scroll (滚动)

- 用于叙事元素和进度指示器。
- 必须使用 GSAP ScrollTrigger 来实现滚动位置与动画进度的精确联动。

## Code Standards (代码规范)

- **HeroUI 集成：** 永远优先使用 `const MotionButton = motion(Button)`，绝对禁止 `<motion.div><Button /></motion.div>` 这种破坏结构的写法。
- **保持语义：** 绝不能为了添加动画而牺牲可访问性或组件语义。
- **明确边界：** 除非有明确的文档说明，否则不要在同一个交互中混用 Motion、CSS 和 GSAP。
- **必须记录：** 任何偏离默认动画技术栈的行为（例如：使用 GSAP 做组件动画），必须在模块文档或 ADR 中记录理由。

## Performance (性能)

- 永远优先对 `transform` 和 `opacity` 进行动画处理。
- 除非绝对必要（若是，请使用 Motion 的 layout 动画），否则避免对触发重排 (Layout) 的属性进行动画处理（如 `width`、`height`、`margin`、`padding`）。
- 确保动画不会导致掉帧，尤其是在长叙事页面上。

## Accessibility (可访问性)

- **减少动态效果：** 系统必须尊重用户的 `prefers-reduced-motion` 设置。
- 复杂的空间动画必须能优雅降级为简单的淡入淡出或瞬间状态切换。
- 如果禁用动画会导致丢失关键的视觉反馈，则应简化动画，而不是完全禁用它。

## Anti Patterns (反模式)

- **为动而动：** 添加没有任何功能性或叙事目的的运动。
- **阻塞用户：** 强制用户等待动画播放完毕才能点击或打字。
- **过度弹跳：** 滥用弹簧效果，导致 UI 感觉松散或卡通化。
- **滥用 Wrapper Div：** 仅仅为了添加 `motion.div` 而破坏 HeroUI 的组件结构。
- **技术混用：** 用 GSAP 做简单的 Hover 状态，或用 CSS 去写复杂的 Layout 过渡。

## Review Checklist (审查清单)

在批准动画代码之前，请核对：

- [ ] 这个动画是否解决了真实的用户问题或清晰地传达了状态？
- [ ] 它是否允许用户随时中断并立即交互？
- [ ] 它是否使用了满足需求的最简单技术方案 (CSS -> Motion -> GSAP)？
- [ ] 如果是 HeroUI 组件的动画，是否使用了 `motion(Component)` 模式？
- [ ] 它是否支持并尊重 `prefers-reduced-motion` (减少动态效果) 的可访问性设置？
- [ ] 它是否存在布局抖动 (Layout thrashing) 或性能瓶颈？
