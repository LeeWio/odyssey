# Odyssey quality matrix

Run only checks that apply to the change. Keep the exact command, result, evidence path or key output, and notes in the task record.

| Check                     | Command / evidence                                                                                             | Guidance                                                                                                                                                                        |
| ------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Preflight                 | `bun run preflight`                                                                                            | Runs Prettier check, ESLint, TypeScript, and unit tests. The CI workflow runs this on PRs, while release/deploy workflows have path filters. Use this as the normal local gate. |
| Unit tests                | `bun run test:unit`                                                                                            | Use focused Vitest tests while iterating, then the full suite for the gate.                                                                                                     |
| API contract              | `OPENAPI_FILE=contracts/nexus-openapi.operations.json bun run api:coverage`                                    | Checks methods and paths against a pinned Nexus revision. Refresh the projection when Odyssey consumes new Nexus operations.                                                    |
| Browser behavior          | `bun run test:e2e`                                                                                             | Run focused scenarios for changes to user journeys when applicable. PRs run the browser smoke suite. The separate full browser workflow runs nightly or on demand.              |
| Production build          | `bun run build`                                                                                                | Required when app code, routes, configuration, assets, or dependencies change.                                                                                                  |
| Accessibility/performance | CI Lighthouse artifact, relevant Playwright checks, and manual keyboard/reduced-motion checks where applicable | Record what was actually exercised. Do not substitute a static typecheck for visual or device evidence.                                                                         |
| Security/dependencies     | `bun audit --audit-level=high`, CI CodeQL, and lockfile review                                                 | Audit the committed Bun dependency graph; report advisory and CI outcomes separately.                                                                                           |

For documentation or Skill-only changes, first record whether the workflow path filters skipped CI. Run the local Skill checks `python3 <skill-creator>/scripts/quick_validate.py .agents/skills/engineering-governance`, `bash -n .agents/skills/engineering-governance/scripts/*.sh`, and an internal-link/file scan. These local checks do not replace CI.

`PASS` means the command actually ran and succeeded. Use `FAIL`, `BLOCKED`, or `N/A` with reasons for everything else. A workflow that did not trigger because of `paths-ignore` is `N/A` or `BLOCKED` with the reason recorded, never `PASS`.
