## 建议开发顺序与验收

### 第一阶段：粘贴的失败语义与真实剪贴板兼容性

- 实现 T1：有类型的解析/粘贴结果、超限提示、失败不改文档、一次成功粘贴只需一次撤销。
- 验收：10,000/10,001 格、1,000,000/1,000,001 字符、畸形引号、CRLF、多行字段、合并格和接近扩表上限；普通文本及代码块仍走原有语义。
- 采集真实 Excel、Numbers、Google Sheets 的 HTML+TSV 样本，覆盖合并格、空格、彩色文本、尾部空列、多行单元格和非 ASCII。当前的合成剪贴板与浏览器测试不能替代真实系统剪贴板矩阵。
- 涉及：`clipboard.ts`、extension options、编辑器反馈层及 unit/e2e fixtures。

### 第二阶段：列宽管理

- 当前 `actions.ts` 的 TableAction 没有“平均分配列宽 / 重置列宽”。为选中列提供这两个明确命令，沿用原生 Dropdown；先确认整表与局部列的规则。
- 合并格必须更新完整 `colwidth` 向量；遵守最小列宽和表容器滚动规则，避免只改 DOM。一个命令对应一个 undo，JSON/HTML 与阅读态一致。
- 验收：不等宽、跨列/跨行、单列、全部列、窄屏、横向滚动后执行，Chromium/WebKit，保存恢复与撤销重做。
- 涉及：`actions.ts`、table node attributes、菜单及 action/unit/e2e 用例。

### 第三阶段：键盘和辅助技术

- 明确宣告所选行/列/单元格范围及操作结果；复用编辑器反馈模式并去重，避免 pointermove 反复播报。
- 保持原生 table 结构；不能为了“像电子表格”直接换成 ARIA grid。
- 验收：Shift+F10、Alt+F10、子菜单方向键、Escape 逐层返回、多编辑器互不干扰、弹窗焦点；使用 VoiceOver/NVDA 做真实辅助技术验证。当前自动化不能代替此项。

### 第四阶段：性能与控制器整理

- 使用 50×20 和 200×20 的代表性内容测量输入、连续选区、列宽拖动、自动滚动的帧耗时与 DOM 测量次数；先记录机器与浏览器基线。
- 若数据表明需要，集中一帧测量并缓存稳定列界；必须在文档交易、列宽拖动、字体/容器尺寸、滚动及合并变化时正确失效，保留 WebKit COL 零宽回退。
- 在现有回归用例保持不变的前提下，提取 `useTableLayout`、`useTableGesture` 或共享 `TableHandle` 中确有重复的职责。命名和边界由实现时的代码证据决定。

## 边界

本轮交付仅包括 4px 外间距、边框中点手柄、原生子菜单恢复及相应交互修复。下一轮不默认加入公式、排序筛选数据库、虚拟滚动或自定义颜色面板。先把写作编辑器里常见的表格操作做到可靠，再根据使用场景扩展。
